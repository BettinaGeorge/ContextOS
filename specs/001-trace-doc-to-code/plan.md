# Implementation Plan: Trace a Spec/Doc to Code

**Branch**: `001-trace-doc-to-code` | **Date**: 2026-07-18 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-trace-doc-to-code/spec.md`

## Summary

Let a signed-in user create one workspace, connect one GitHub repository and one Notion source, and ask a question that requires tracing a Notion doc to the code that implements it — returning a synthesized, cited answer that distinguishes deterministic evidence from inference and explicitly abstains when evidence is insufficient. Technical approach: FastAPI backend ingests both sources into a shared Postgres+pgvector artifact/relationship model, extracts deterministic links first (explicit URLs), falls back to vector similarity search when no deterministic link exists, and validates every citation against retrieved evidence before returning an answer generated by Claude.

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript / Next.js 15, App Router (frontend)

**Primary Dependencies**: FastAPI, Pydantic v2, SQLAlchemy 2.0 + Alembic, `pgvector` (Python package), Anthropic SDK, Voyage AI SDK, `supabase-py` (Auth verification + Postgres client), PyGithub or direct GitHub REST via `httpx`, `notion-client`; Next.js, React, Tailwind, shadcn/ui

**Storage**: PostgreSQL + pgvector, hosted on Supabase free tier (per ADR-001)

**Testing**: `pytest` + `pytest-asyncio` (backend), `vitest` + React Testing Library (frontend)

**Target Platform**: Web — backend on Render free web service tier, frontend on Vercel free tier

**Project Type**: Web application (frontend + backend)

**Performance Goals**: No hard throughput target — single user, single workspace in this phase. Informal target: an answer (including LLM generation) returns within ~30s; ingestion of one repo + one Notion source completes without the user needing to babysit it.

**Constraints**: Total spend capped at $10, non-recurring (ADR-001) — this directly shapes the job-processing design below (see research.md, "in-process job polling vs. separate worker"). Render free-tier cold starts are an accepted UX cost, not a defect. Workspace-isolated data model even though only one workspace is exercised.

**Scale/Scope**: 1 user, 1 workspace, 1 GitHub repository, 1 Notion source, 1 workflow (spec.md Assumptions).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked after Phase 1 design.*

| Principle | Check | Result |
|---|---|---|
| I. Evidence-Backed Answers | Plan includes an explicit citation-validation step (`answer_svc`) between retrieval and response — no citation reaches the user unless it was actually retrieved. | PASS |
| II. Deterministic Before Inferred | Plan resolves deterministic links (explicit URL match) before falling back to vector similarity, and the response schema (contracts/api.md) carries an `origin` field per citation so inferred evidence is never presented as certain. | PASS |
| III. Untrusted Content Boundary | Plan isolates ingested content into the evidence packet passed to the LLM as data, never concatenated into the system prompt as instructions; no ingested code is executed. | PASS |
| IV. Spec-Driven Development | This plan follows spec.md; no code precedes it. | PASS |
| V. Narrowest Credible Scope | Single repo, single Notion source, one workflow, Postgres-backed job table instead of a queue, no graph DB, no multi-provider LLM abstraction — matches ADR-001 exactly. | PASS |
| VI. Workspace Isolation | Every table in data-model.md carries `workspace_id`. | PASS |
